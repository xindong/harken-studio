Use Harken Hub from a terminal

The CLI lets you manage projects, Studio versions and Unity integration packages without opening the Hub window. It uses the same project list and settings as Hub. Opening or creating a project still starts Studio.

1. Run your first command

Open PowerShell in the folder containing HarkenHub.exe and run:

./HarkenHub.exe --cli projects list | Out-String

You will see JSON: structured text that people and automation can both read. ok: true means the command succeeded. Your results are under data. In a different directory, use the full executable path; keep paths containing spaces inside quotes.

& "C:/path/to/HarkenHub.exe" --cli help

On macOS, invoke the executable inside the Hub application bundle from Terminal. The command words and options are the same. The help command lists the commands supported by your installed build.

In an interactive PowerShell window, append | Out-String to wait for this Windows desktop executable and display its complete output. Scripts should wait for the process to exit before reading its exit code; in PowerShell, read $LASTEXITCODE after the pipeline completes.

Reopen an already running Hub window to reload appearance and language choices. Automatic update choices notify the background service immediately; enabling one starts the service if needed, without opening a Hub window.

3. Review before changing files

Installing, repairing or removing files uses two steps. First run the command without confirmation. Hub returns a plan and a confirmation token. Read the plan, then repeat the same command with --confirm TOKEN.

./HarkenHub.exe --cli versions install --package "D:/Downloads/Studio.zip" --manifest "D:/Downloads/release.manifest"
./HarkenHub.exe --cli versions install --package "D:/Downloads/Studio.zip" --manifest "D:/Downloads/release.manifest" --confirm TOKEN

Use the exact package and manifest paths returned by the download command. TOKEN is a placeholder for the token you just received. If the files or options change, the old token stops working. Read the new plan before confirming again. Windows may ask for administrator permission to install, repair or uninstall Studio.

Removing a project from the Hub list (projects remove) or removing a local build registration (versions remove-local) keeps its files. versions uninstall removes an installed Studio version.

4. Choose Unity integration contents

./HarkenHub.exe --cli integrations install --path "D:/UnityGame" --source "D:/Integration/Harken"

Core integration is included. API documentation and samples are omitted by default. If old copies exist, Hub asks you to decide before generating an executable plan:

ChoiceMeaning
keepKeep the existing copy.
updateCopy the version from the selected source.
removeBack up and remove files managed by Hub; keep your own files.
./HarkenHub.exe --cli integrations install --path "D:/UnityGame" --source "D:/Integration/Harken" --documentation keep --samples remove

Read the returned file list, then repeat with its confirmation token. Use --documentation update --samples update if you want both optional components. Keep Unity closed during changes. Samples copied or imported elsewhere remain outside Hub's ownership.

To remove an integration, use integrations remove --path "D:/UnityGame" --backup "D:/Backups/Game-integration-01". Choose a new backup directory and keep that same path when confirming. Move and restoration commands follow the same review process; see the reference for their parameters.

5. Updates, agreements and errors

Use updates download --product hub, then updates apply --product hub to review a Hub update. Use studio for Studio. After confirmation, Hub updates close running Hub windows and the background service, use the update bridge, and restart the background service. A queued result is not a completed installation; check updates status and diagnostics transactions.

If Hub asks for agreement acceptance, read legal show --product studio (or hub). Only if you accept the displayed documents, run legal accept --product studio, review the response and repeat with its token.

Exit codeWhat to do
0The command succeeded. Read the returned result.
2Correct the command or parameter using help.
3Read the error and operation steps; resolve the cause before retrying.
4Make any requested content decisions, review the plan and confirm.
5Read and decide whether to accept the current agreements.

Do not let a script blindly reuse newly returned confirmation tokens. Each new plan needs a fresh review. For automation, use the AI command reference and JSON contract.
