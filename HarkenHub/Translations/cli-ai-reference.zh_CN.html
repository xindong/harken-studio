Harken Hub CLI：AI 命令参考

本页的命令和参数清单由 CLI 解析器的同一份定义生成。执行 HarkenHub --cli help 可获取当前可执行文件支持的契约。下方命令、参数名及机器契约使用英文，便于直接交给 AI 或脚本读取。

启动进程时，将每个参数作为独立字符串传入；通过终端执行时，给含空格的路径加引号。不要把用户输入拼接成 shell 代码。所有选项都需要一个字符串值；布尔值只能写 true 或 false。未知命令、未知或重复选项、缺失值和非法枚举值会在执行前被拒绝。

读取结果

标准输出为一个 UTF-8 JSON 对象，含 schemaVersion 和 ok。同时检查进程退出码。退出码 0 表示命令成功；2 为参数错误；3 为操作失败；4 表示需要检查清单并确认；5 表示需要接受协议。失败信息可能位于 error，也可能位于 data.steps，报告问题时保留完整结果。

集成步骤的 status：0 待执行，1 执行中，2 成功，3 警告，4 失败，5 跳过。

新建或打开工程会启动 Studio；Hub 更新可能只是交给更新桥接服务排队执行。上述返回成功不代表另一个进程已经完成。用返回的事务编号及 updates status、diagnostics transactions 继续核实结果。CLI 自身不打开 Hub 窗口；安装、修复或卸载版本可能出现操作系统的管理员授权提示。

Unity 集成包以 package.json 识别。安装成功仅表示已审阅的文件操作完成，不验证 Unity 编译、播放或目标平台支持，也不执行原生运行库的平台预检。这些能力需在 Unity 中测试。安装或升级会用所选集成包整体替换安装目录，用户在目录内的修改或新增文件不会保留，需提醒用户用版本控制保存需要的修改。安装目录必须为空或已是 Harken 集成；集成创建的工程设置位于安装目录之外，不受影响。

确认流程

成功的工程响应可能包含 data.warnings，表示版本保留记录未能刷新；工程改动已提交，不要重复执行已完成的移除。修复计划的 changes 列出新增、替换、删除和保留项，包括非受管文件的删除。出现 ReviewChanged 错误时，去掉 --confirm 重新执行，并请用户审阅新计划。

对于 reviewBeforeApply 命令，先不带 --confirm 执行，向用户展示返回的计划。用户同意后，以完全相同的参数加上 --confirm TOKEN 执行。文件或选项变化会使旧标识失效；不能自动接受新标识，必须重新检查计划。

修改集成前请关闭 Unity。

安装或移除期间，Hub 会临时备份原有的集成目录。操作失败或中断后，integrations restore 可恢复该版本；操作成功后备份会被删除。

接受协议是单独的用户决定。先用 legal show 展示完整文档，只有用户明确接受后，才提交 legal accept 返回的确认标识。
