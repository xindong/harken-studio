# 三支柱世界观

## Engine：一条神圣的线

```
                     ┌─────────────────────────────────────────┐
   逻辑线程 ──命令──▶ │  音频线程：排空命令 · 逐 voice 渲染级联   │ ──▶ 设备/空后端
   (拥有公开 API)     │            · 折叠 bus 图 → master        │
        ▲            └───────────────▲─────────────────────────┘
        │                            │ 只读
     备料 / 交接                  流环(无锁)
        │                            │
   媒体 · 流式线程 · 热重载 · 停泊 ───┘         快照 · 远程控制 ── 在一旁观察
```

引擎承担**执行**。它对"上面是谁在用"一无所知，也刻意不去知道，玩法的多样性被推给上层，引擎把省下的全部预算投
在实时正确性上。引擎对外只有一套 C 风格的原语：普通结构体与函数，统一
前缀，按族区分的结果码。引擎的全部结构，都可以理解为围绕**一条线**的编排——那条线就是音频线程。只在预先备好的内存上做确定量的计算，绝不阻塞、绝不分配、
绝不碰文件系统。

## Studio：创作的真相之源

编辑器承担**建模**：声音设计师在这里把对象**创作
出来**——组织内容、接线参数、划分总线、编排行为——而引擎负责执行、SDK 负责
唤起。因此编辑器坐在整条数据旅程的**源头**：

```
 [编辑器] 创作 ──▶ 工程静态存储（真相之源）
                        │ 一次转换
                     媒体缓存（派生、可重建）
                        │ 编译
                     部署包 ──▶ [引擎] 加载并执行
```

**编辑器坚决不做什么：**

- **不渲染音频。** 一切发声都在引擎的实时线程上发生；编辑器要听声音，是驱动引擎
  去发，而不是自己混音。
- **不绕过接缝碰引擎内部。** 除了那道唯一的运行时桥，编辑器不假设、不依赖引擎的
  任何内部形状——桥的另一侧换代重写，编辑器不应察觉。
- **不把派生物当真相。** 媒体缓存与部署包都是从工程编译出来的；它们可以丢、可以
  按平台重建，唯一不可再生的是工程本身。

## SDK：薄投影，加法为零

三支柱里，SDK 是最薄的一根。引擎负责*渲染*、编辑器负责*创作*，而 SDK 只做一件
事：**把游戏对声音的一次意图，翻译成引擎早已认识的一条原语命令。**

SDK 处在数据旅程的触发端，承接的是信息最少、最纯、最快的一段。因此它的全部
工作可以概括为**把一个稳定名字，尽快、尽廉价地换成引擎认识的一次原语调用**——
翻译收敛在**装载时一次完成**：把名字解析成稳定 id，此后只带着 id 触发。

**SDK 刻意不承担的：**

- **不持有引擎状态**——它是无状态的转述者，状态住在引擎里。唯一必要的例外是把
  引擎回调接回游戏的那座桥，它因职责所迫持有少量托管状态。
- **不引入引擎没有的概念**——顺手的名字可以有，新的动词不可以。
- **不把宿主表示泄漏给 Core**——坐标手性、轴向和距离单位在对应宿主适配层一次
  收敛，Listener 与 Emitter 必须经过同一转换。
- **不在热路径上分配**——把垃圾回收负担挡在每帧调用之外。
