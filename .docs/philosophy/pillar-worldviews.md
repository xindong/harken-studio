# 三支柱世界观

## Engine：一条神圣的线

```
                     ┌─────────────────────────────────────────┐
   逻辑线程 ──命令──▶ │  音频线程：排空命令 · 逐 voice 渲染级联   │ ──▶ 设备/空后端
   (拥有公开 API)     │            · 折叠 bus 图 → master        │
        ▲            └───────────────▲─────────────────────────┘
        │                            │ 只读
     备料 / 交接                  流环(无锁)
        │                            │
   媒体 · 流式线程 · 热重载 · 停泊 ───┘         快照 · 远程控制 ── 在一旁观察
```

引擎承担**执行**。它对"上面是谁在用"一无所知，也刻意不去知道，玩法的多样性被推给上层，引擎把省下的全部预算投
在实时正确性上。引擎对外只有一套 C 风格的原语：普通结构体与函数，统一
前缀，按族区分的结果码。引擎的全部结构，都可以理解为围绕**一条线**的编排——那条线就是音频线程。只在预先备好的内存上做确定量的计算，绝不阻塞、绝不分配、
绝不碰文件系统。

## Studio：创作的真相之源

编辑器承担**建模**：声音设计师在这里把对象**创作
出来**——组织内容、接线参数、划分总线、编排行为——而引擎负责执行、Integration 负责
接入游戏宿主。因此编辑器坐在整条数据旅程的**源头**：

```
 [编辑器] 创作 ──▶ 工程静态存储（真相之源）
                        │ 一次转换
                     媒体缓存（派生、可重建）
                        │ 编译
                     部署包 ──▶ [引擎] 加载并执行
```

**编辑器坚决不做什么：**

- **不渲染音频。** 一切发声都在引擎的实时线程上发生；编辑器要听声音，是驱动引擎
  去发，而不是自己混音。
- **不绕过接缝碰引擎内部。** 除了那道唯一的运行时桥，编辑器不假设、不依赖引擎的
  任何内部形状——桥的另一侧换代重写，编辑器不应察觉。
- **不把派生物当真相。** 媒体缓存与部署包都是从工程编译出来的；它们可以丢、可以
  按平台重建，唯一不可再生的是工程本身。

## Integration：接入宿主，明确归属

引擎负责*渲染*、编辑器负责*创作*，Integration 承担**游戏引擎与其他宿主的接入**：
把游戏对声音的意图交给引擎执行，并让会话、资源、回调与组件遵循宿主的生命周期。

SDK/API 绑定提供开发者调用引擎的接口，其中的原生投影应忠实保持引擎合同。
Integration 使用这些接口完成具体宿主的适配，还承担内容准备、资源引用、更新驱动、
暂停恢复、关闭和编辑器接入。薄投影是接口绑定的边界，不能概括整个集成层的职责。

**Integration 的状态与边界：**

- **宿主状态有明确所有者**——集成层持有会话、资源引用、回调注册及组件关联所需的
  状态，并在宿主生命周期结束时释放；声音的执行状态和音频语义仍归引擎。
- **不重写引擎语义**——宿主可以有便利入口和生命周期封装，播放、变量与混音的
  含义仍由引擎决定。
- **不把宿主表示泄漏给 Core**——坐标手性、轴向和距离单位在对应宿主适配层一次
  收敛，Listener 与 Emitter 必须经过同一转换。
- **不在热路径上分配**——把垃圾回收负担挡在每帧调用之外。
