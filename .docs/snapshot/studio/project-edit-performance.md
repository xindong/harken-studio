# Studio 大型工程编辑性能

这份记录保留第一轮优化的数据。后续针对启动、首存、路由保存与曲线首次打开所做的修改和当前实测，见[第二轮复核](project-open-save-performance.md)。

2026-11-27，Windows x64，Intel Core Ultra 7 265K，Qt 6.8.3，RelWithDebInfo。基线为 `eb25581a`。每次在 `saga2_audio` 的独立完整副本上测试，包含 806 份对象文档、441 个 Sound、362 份音频和四个平台。

## 卡顿从哪里来

10 月的优化已经为普通音量、蓝图和保存建立了轻量路径。之后加入滤波器、跨平台 FX 和 Conversion 时，工程树沿用了保存、重命名和移动后的全树刷新入口。11 月的 `3f50b1f9` 和 `6be867ef` 使每个有可用媒体的 Sound 行为了准备悬停文字，各自解析全工程的字段组。基线一次空保存查询 441 次，单是这一步就占 1,384–1,403 ms。移动一个 Action 连同紧随其后的排队刷新共查询 2,205 次。10 月 22 日已经有人用同名工程报告 Inherit 卡顿，继承编辑还存在独立的重复求值开销。[历史继承问题](https://github.com/xindong/harken-studio/issues/93) · [参数编辑优化](https://github.com/xindong/harken-studio/pull/151) · [增量保存优化](https://github.com/xindong/harken-studio/pull/194)

这次收敛了四条实际调用路径。

| 入口 | 现在每次操作做什么 |
| --- | --- |
| 工程树 | 常驻行更新名称、脏标记、图标和颜色。Qt 读取提示时按 GUID 获取当前对象及其媒体状态，转换查询共享一次已解析配置。搜索启用时建立重名消歧索引。Original 预览只维护它需要的运行时状态。 |
| Inspector | 一次刷新内共享来源索引、字段组求值和各平台的校验结果，dirty 通知不再引发整页重绑。拖动首个样本完整验证，后续数值样本复用编辑规则，沿当前对象的所有权祖先链求值。释放沿用正式提交、过期状态检测和撤销入口。刷新之外对继承来源提示的查询读取当前名称和覆盖状态。 |
| 衰减曲线 | 一次改动的引用者使用同一次批量运行时同步，五个引用者共用一份快照，各个对象仍收到各自的字段通知。 |
| 打开与保存 | 基线复用打开时的文档读取上下文和已有的对象序列化结果。相同 Schema、GUID 到文件路径映射及根 Bus 下复用未改文档的依赖分析，大读集的路径检查使用现有线程池。事务仍在准备、提交时核验外部变化。 |

## 参数、继承与曲线

四平台选中根 Layer 的真实 Inspector 控件，每项正式操作重复 3 次。计时覆盖同步 Qt 槽，排队槽和下一帧绘制另计。独立的原生主窗口测试通过作者命令切换继承、操作曲线、撤销重做，逐次读回状态。

| 操作 | 原版 ms | 第一轮 ms | 优化后 ms |
| --- | ---: | ---: | ---: |
| 四平台输出音量提交 | 309.4 | 52.0 | 31.8 |
| 四平台输出音量撤销 | 375.3 | 45.2 | 26.9 |
| 四平台普通音量撤销 | 202.2 | 10.7 | 3.9 |
| 四平台输出音量拖动，每手势 5 个样本 | 18.33/步 | 5.64/步 | 首步 5.60，后续 0.034/步 |
| Shared 切 Inherit，主窗口 | 1,494 | 31 | 30 |
| Windows 切 Inherit，主窗口 | 1,483 | 32 | 31 |
| Windows 切 UseShared，主窗口 | 1,502 | 32 | 30 |
| 曲线新增点，主窗口 | 33.9 | 31.6 | 16.2 |
| 曲线移动点，主窗口 | 32.7 | 27.8 | 16.7 |

第一轮后，输出音量提交仍要 52 ms。第二轮让效果行和衰减控件共享同一份页面数据，并把一次数值手势中重复的全工程验证收敛到首个样本与正式提交。四平台输出音量提交的全工程快照从 58 次降到 5 次，撤销从 70 次降到 5 次。最后一次行为复查发现，保留旧视图再改名可能显示旧的继承来源。修正后，改名、覆盖变化和来源删除均通过读回检查。

单独向真实曲线控件投递按下、连续 8 次移动和释放的鼠标事件。每步移动约 0.013 ms，释放提交从 27.6 降至 6.8 ms，快照从 5 份降到 1 份。三个手势均核对预览、完成的曲线点及手柄、通知名单和顺序，以及撤销和重做。前后使用同一组其他构建对象，只更换衰减存储实现。

工程树另在 Hierarchy 和 ProjectExplorer 两个实际面板中抽查。同名对象在搜索时显示各自的完整路径，清空搜索后恢复短名。重命名父、子对象后，同一个现有树行的提示反映新名称和路径，并保留原 GUID。

在另一组副本上，以实时空音频设备播放 `Mus_Login`，在播放中将 Sound 音量设为 −96 dB 并撤销。两版的 Mus 母线电平均降至 −96 dB，撤销后均读得 −20.94 dB。期间播放句柄一致，始终只有一个活跃声部，停止后归零。这项抽查验证了实际引擎渲染、编辑与撤销的衔接。

## 首次保存和稳态保存

这份工程在打开前已经是 Schema 10。版本分析只在来源版本小于目标版本时创建迁移计划。普通打开仍会比较文件内容与当前写出格式，将差异登记到保存基线。案例中 630 个对象缺少仅含默认滤波器的 `mixnode`，另 1 个已有 `mixnode` 的对象缺少 `filter`，根文档缺少空的 `defaultConversions`。打开阶段写入 0 份受监测文件，首存写入 632 份，紧接着空保存写入 0 份。[版本判断](../../../HarkenStudio/Source/Core/ProjectUpgradeManager.cpp) · [保存基线](../../../HarkenStudio/Source/Core/ProjectManager.cpp)

独立常驻 CLI 交替运行四轮，每轮 14 次保存。对 807 份权威工程文档和 1 份资产注册表逐份计算 SHA-256，并用文件时间、大小、内容和增删检测实际触碰路径。每一步的内容和触碰路径都与原版一致。桌面原工程的这 808 份文件及 362 份音频也与审计初期副本完全一致。

又用最终 CLI 首存一份原样副本，退出进程，启动新进程重新打开同一副本，再执行保存。按 SHA-256 和修改时间比对 808 份文件，新进程的打开、保存各触碰 0 份。

| 独立 CLI 保存 | 每版样本 | 原版中位 ms | 优化后中位 ms |
| --- | ---: | ---: | ---: |
| 原样副本首次保存 | 2 | 3,048 | 3,111 |
| 已规范化工程空保存 | 4 | 37 | 37 |
| 音量修改后保存 | 6 | 96 | 102 |
| 输出 Bus 变更后保存 | 10 | 403 | 258 |
| Bus 重命名后保存 | 4 | 490 | 367 |

首存、空存和普通音量保存的独立 CLI 对照未测出加速。单独的首存阶段探针中，约 89% 用于准备、应用和提交 632 份文件的事务，候选对象序列化耗时 41 ms。该探针与测试并行，仅用于判断开销分布。路由变更仍会触发全局关系验证。大工程在本机首次打开仍约 4.5 秒，曲线面板首次打开约 163 ms、提交后立即读回约 50 ms。这批性能数字覆盖 Windows 命令往返或控件同步处理，物理输入到呈现的延迟、硬件试听和其他操作系统需要分别测量。

## 复核入口

本机完整记录和脚本位于 `.local/studio-performance-optimization/`，其中 `project/` 是主窗口配对序列，`inspector/` 是控件和预览语义，`operations/` 是继承和曲线，`storage/` 是事务与文件对照，`history.md` 记录可回溯到旧库的提交。主窗口脚本从桌面复制案例，原版与优化版解析相同的作者命令。新增编辑或显示功能时，可在相同副本上复跑命令、下一条读请求和文件检查点，并对比完整快照次数。

正式验证使用以下入口。最终 Studio 目录的 CTest 为 676 项通过，失败和跳过均为 0。跨属性的数值预览与正式编辑一致性已经加入现有测试套件，可在后续构建中持续验证。另以 384 组输入对照两条路径的接受、拒绝及完整状态，覆盖继承、平台覆盖、所有权和无效数值。[回归用例](../../../HarkenStudio/Test/UnitTest/FieldGroupProjectAdapterTest.cpp)

```powershell
cmake --build build-nc --config RelWithDebInfo --target harken_studio harken_studio_cli harken_studio_tests harken_project_schema_tests harken_bus_compiler_tests
ctest --test-dir build-nc/HarkenStudio/Test -C RelWithDebInfo --output-on-failure -j 7
```
