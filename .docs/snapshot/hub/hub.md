# HarkenHub 现状快照

## 产品边界

| 项目 | 现状 |
|---|---|
| 定位 | 分发与启动器，不链接音频引擎 |

## 官方还原与发布协议

新增签名字段 `packageManifest` 包含 `fileName`、`size`、`sha256`。文件名固定为 `<version>-<buildId>.files.json`，最大 16 MiB；下载位置只从原发布包所在对象目录和同一 GitHub Release 推导。清单还需匹配产品、版本、构建和渠道；拒绝越界路径、设备名、ADS、大小写／Unicode 别名、重复文件与文件目录冲突。清单与 ZIP 共用 `Packaging/PackageInventory` 解析，下载过程中限制长度，缓存每次重新核验。

`Integrations/OfficialUnitySource` 在独立暂存目录按官方文件列表复制并再次核验候选包；额外本地文件不会进入还原来源。候选不完整或哈希不同则下载、核验和提取完整包，同时检查内嵌清单与独立清单字节一致。原版本的历史签名允许过期，但仍严格验签并绑定明确构建；不将该策略用于自动选择升级版本。当前入口每次从在线发布目录查找确切构建，目录不可用时停止；不静默信任离线来源。

新安装记录保存随附 Studio 清单中的构建来源提示。来源提示和版本号本身不构成真实性证明；还原前仍要求已安装记录的受管路径与原始哈希匹配官方清单，兼容已有文本归一化哈希。旧记录可使用原关联来源定位具体构建；信息不足、构建下架或记录与官方原版不匹配时停止，不猜测同版本的其他构建。

还原按官方原始字节写回，包括受管 `.meta`；项目生成的非受管 `.meta` 和根目录 `.meta` 保留。P4 签出、只读、文件锁和 Unity 占用由预检报告，不自动解除保护。还原的暂存和永久备份，以及卸载后重装保留的文件，均保留原读写执行权限及 Windows 只读属性，避免目录切换使未修改的受管文件或用户文件变为可写。确认绑定目标快照、官方来源、文件哈希和备份位置；执行前再次检查。`Library/HarkenIntegration/pending-restore.json` 与永久备份中的 `backup.json` 保存相同恢复记录。恢复入口先核验项目锁、路径、记录和备份，再处理已验证的切换边界，不因暂时缺少内嵌包而被 Package Manager 的原有依赖声明阻断；现场或备份已发生未知变化时保留所有目录并报告冲突。

构建脚本将独立清单加入发布证据与 CI 产物。独立调用 `.scripts/release/sign_release_manifest.py sign` 时传入 `--package-manifest`，脚本核对清单与 ZIP 字节及身份后纳入签名。正式发布入口位于 **audio-harken-managing-tool** 仓库的 `publishing/core.py`：从最终 ZIP 提取独立清单、签名、双源上传并验证，之后才更新公开版本目录。部署更新的发布器和 Hub 后，新发布启用节省下载量的路径；历史发布保持原签名与完整包回退行为。
